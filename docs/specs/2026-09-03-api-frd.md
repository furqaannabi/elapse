# Platform API (`api/` — REST + Postgres) — FRD

Status: **Draft — awaiting human sign-off** · Surface: Platform (merchant-facing REST, internal ingest, dashboard backend) · Sources: detailed doc §2, §3 Objects, §4.2 frozen SDK surface, §4.4, §5.1–5.3, §6 item 7 & 9, §8, §9 Architecture, §12 Week 2/4, §15; `api/README.md`; `.env.example`; checkout FRD (Data block, BR-CHK-005); dashboard FRD outline; design brief §3.

## Problem

Merchants must integrate "in an afternoon" with the nouns they already know from Stripe (doc §2, §3). The API is the only thing the SDK, the hosted Checkout, the dashboard and the docs talk to. It owns the truth about Merchants, Products, Customers, Checkout sessions, Subscriptions, Invoices/Settlements, Webhook endpoints, Events and Deliveries; it turns indexed chain events into merchant Events; and it must serve exactly the frozen §4.2 surface — "anything not listed does not exist" (§15).

## User stories

1. As a Merchant engineer, I want `products.create` and `checkout.sessions.create` with my secret key and get back `session.url`, so that the quickstart takes under 10 minutes (§6).
2. As a Merchant engineer, I want `GET /v1/subscriptions/:id` with `rate` and `started_at`, so that I can compute a live meter locally without per-second webhooks (§5.1).
3. As a Merchant, I want separate test and live keys, hashed at rest and shown once, so that a leaked database does not leak my keys (§9).
4. As the hosted Checkout, I want to load a session with only a publishable key and a session id, so that the secret key never reaches the browser (BR-CHK-005).
5. As the indexer, I want an ingest endpoint that accepts the same chain event twice without side effects, so that Envio preload double-fires are harmless (§15).
6. As a demo presenter, I want test clocks in test mode, so that the video shows an hour of accrual in seconds (§6 item 9).
7. As a judge, I want a published OpenAPI document that matches the SDK, so that the docs are not a lie (§6 item 7, §15).

### Ingest from the indexer (doc §5.2 step 2–3, §15 "idempotent on txHash+logIndex")

| Id | Requirement | Acceptance |
| --- | --- | --- |
| FR-API-070 | `POST /internal/ingest` authenticated with `Authorization: Bearer $INGEST_TOKEN` (shared secret, not a Merchant key). Body: `{chain_id, block_number, block_hash, block_timestamp, tx_hash, log_index, address, event_name, args}`. Unique index on `(chain_id, tx_hash, log_index)`; a duplicate returns `200 {duplicate: true}` and does nothing else. | Post the same body twice → one `chain_events` row, one Event. |
| FR-API-071 | Mapping (stream `address` → Subscription): `StreamStarted` → `active`, `started_at`; Events `checkout.session.completed` + `subscription.created`. `StreamPaused r=0`/`StreamResumed` → `paused`/`active`; `subscription.updated`. `StreamPaused r=1` → `paused`; `invoice.payment_failed` (+ FR-API-051). `Settled` → Invoice + `invoice.settled`. `StreamCanceled` → `canceled`, `canceled_at`, `seconds_elapsed`, `amount_settled`; `subscription.canceled`. `StreamCreated`, `Deposited` → update `stream_address`/`funded_usd`, no merchant Event. | One fixture per chain event; assert Events created and Subscription fields. |
| FR-API-072 | Ingest for an unknown `address` (not a platform-created stream) is stored and ignored (`200 {ignored: true}`). Ingest for a mode mismatch (chain 10143 event on a live Subscription) → `409`. | Tests. |
| FR-API-073 | Event creation and Delivery job creation happen in one Postgres transaction (worker FRD FR-WRK-001), so an Event never exists without its jobs. | Transaction rollback test. |
| FR-API-074 | `GET /v1/status` (public): `{chain_id, contracts{factory}, indexer{latest_block, head_block, lag_seconds, last_ingest_at}, worker{queued, oldest_queued_age_s}}` for judge mode (checkout FRD FR-CHK-011; indexer FRD FR-IDX-040). | Returns within 500 ms with mocked indexer. |

### Conventions (Stripe-like; doc §3 "Mirror Stripe")

| Id | Requirement | Acceptance |
| --- | --- | --- |
| FR-API-080 | Lists: `?limit=` (1–100, default 10), `?starting_after=<id>`, response `{object:"list", data:[], has_more, url}`; newest first. | Cursor test across 25 rows. |
| FR-API-081 | `Idempotency-Key` header on every `POST`: same key + same body within 24 h → replay the stored response; same key + different body → `400 idempotency_error`. | Tests. |
| FR-API-082 | Error shape `{error: {type: api_error|authentication_error|invalid_request_error|rate_limit_error|idempotency_error|not_found, code?, message, param?}}`; ids that exist in another mode return `404`, never `403`. | Snapshot tests. |
| FR-API-083 | Wire format is `snake_case` JSON (§5.3); the TS SDK maps `rateUsdPerSecond → rate_usd_per_second`, `successUrl → success_url` (Undecided 2). Ids carry object prefixes; every object has `object` and `created`. | Contract test between `sdk/ts` and `openapi.json`. |
| FR-API-084 | `openapi.json` is generated from route schemas (Zod/`@hono/zod-openapi` or equivalent), served at `GET /openapi.json`, and published into docs (§12 Week 4). Every SDK method in §4.2 has exactly one operation; no operation exists that the SDK/docs do not list, except dashboard-internal and `/internal/*`. | CI diff between SDK method list and OpenAPI operationIds. |

## Business rules

| Id | Rule |
| --- | --- |
| BR-API-001 | Test and live data never mix: every table has `livemode`; every query is scoped by the key's mode (BR-DSH-002). |
| BR-API-002 | The indexer never holds Merchant secrets; ingest uses one platform token and carries no Merchant identifiers (§5.2). |
| BR-API-003 | Secret keys and webhook secrets are shown once; the API never returns them again (BR-DSH-001). |
| BR-API-004 | Money is decimal strings on the wire and `NUMERIC`/bigint in Postgres; never floats (BR-MTR-001). `rate_usd_per_second` must be exactly representable in token base units or is rejected (BR-CON-005). |
| BR-API-005 | Subscription status is derived only from ingested chain events (or the test clock); an API call can request a change but never sets `active/canceled` itself. |
| BR-API-006 | Only the six §5.1 event types exist. No `invoice.tick`; nothing per second (§5.1). |
| BR-API-007 | The frozen §4.2 surface is servable end-to-end by Week 2 (`products.create`, `checkout.sessions.create`, `constructEvent`) and in full by Week 4. |
| BR-API-008 | `amount_settled` and `seconds_elapsed` in Events are cumulative totals for the Subscription, matching `StreamCanceled` (FR-CON-024). |

## Undecided (human)

1. **Framework.** Decided 2026-09-03 (Furqaan): **Bun + Hono**, separate `api/` service; the worker shares its codebase and runs as a second Bun process.
2. **Wire casing.** (a) `snake_case` on the wire, SDK maps frozen camelCase request keys and returns responses as-is (= SDK FRD Undecided 1 option b); (b) camelCase everywhere. **Recommend (a)** — §5.3 payload and cURL docs are snake_case.
3. **Pause/resume exposure.** (a) dashboard-internal only; (b) public `POST /v1/subscriptions/:id/pause|resume` and SDK methods; (c) drop pause for 13 Oct. **Recommend (a)** — §15 freezes the SDK.
4. **Test mode semantics.** (a) test = Monad testnet 10143 with real streams, test clocks only for `simulated` Subscriptions; (b) test = fully simulated, no chain; (c) test = local anvil with `evm_increaseTime`. **Recommend (a)** — the kill gate is on testnet anyway.
5. **Key roll grace window.** 0 / 1 h / 24 h. **Recommend 1 h.**
6. **Rate limits.** 100 req/s per sk_, 20 req/s per pk_, 10 `POST /v1/checkout/sessions` per second per Merchant. **Recommend these** and revisit only if the demo hits them.
7. **Webhook secret at rest.** (a) encrypted with `WEBHOOK_SECRET_KEK` (worker can sign); (b) hashed (worker cannot sign — infeasible). **Recommend (a)**; API keys stay hashed.
8. **Merchant id prefix / dashboard auth.** `mch_` and magic-link email (dashboard FRD Undecided). **Recommend `mch_`, magic link.**
