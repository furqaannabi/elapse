# Judges get into a shared demo merchant account with one click
2026-10-02 · Decided by Furqaan · Status: accepted; partly superseded by [2026-10-02 examples on the demo merchant](./2026-10-02-examples-on-the-demo-merchant.md)

## Context
The submission form asks for "steps to try your product, including any test login details". Anyone can already sign in to the dashboard with their own email — the first magic link creates a merchant — but that merchant opens empty, and the link costs a trip to an inbox. Furqaan chose a shared, pre-filled demo account a judge reaches with one click, over "sign in with your own email", accepting that a button published in the form is effectively public.

The choices that followed, in the order they were grilled: a **separate** demo merchant rather than the one the examples run on, so nothing a judge does can stop Northwind or Acme GPU; **writable** in test mode and restored on a schedule, rather than read-only or a copy per judge; a **deny-by-default allowlist** of what the demo session may write; history from **real** testnet meters rather than rows inserted into Postgres, whose fake tx hashes would link to nothing; the configuration reset run by the **worker** every six hours rather than a systemd timer or a lazy reset at sign-in; deliveries to a **sink inside the API** that verifies signatures as a merchant would, rather than the SaaS example's route or a third-party catcher; one-click **POST** sign-in at `/login`, behind a **six-digit permanent PIN** added afterwards so the public button does not let in anyone who finds it; a merchant identified by a **flag** and an unreachable email; and a **throwaway wallet** for the seed meters rather than a stored key or the faucet's.

## Decision
One merchant carries `demo = true` (at most one, enforced by a unique partial index), named "Acme Cloud (demo)", with the email `demo@elapse.invalid`, which can never receive mail; the magic-link route refuses that email, so the only way in is the **Try the demo account** button on `/login` (highlighted at `/login?demo=1`) and a **six-digit permanent PIN**. The PIN lives in `DEMO_PIN` on the host — never in the repository, which is public, and never logged — is compared in constant time, and changes only when that variable does; without it demo sign-in is off. Five wrong PINs per IP in 15 minutes, or 200 across everyone in an hour, pause demo sign-in for that IP or for everyone until the window passes. A correct PIN POSTs to a hidden route that mints an ordinary HttpOnly session marked `demo`, lasting 24 hours, limited to 20 per IP per hour; each sign-in is its own session.

A demo session may write only what an allowlist names, in test mode only: products (create, edit, archive), webhook endpoints (create, edit, delete, roll secret, send test), test API keys (create, roll, revoke), event and delivery resends, checkout sessions, notifications read, and the dashboard faucet. Everything else — every live-mode write, the profile, the payout address, the logo, Delete test data, and any route added later — answers 403 "Not available in the demo account". The dashboard keeps its buttons, shows the refusal as a toast, and carries a banner offering the judge their own account.

A `demo:seed` script, run once inside the API container, creates or finds the demo merchant, two products ("GPU time" at $0.004/s and "Inference API" at $0.0005/s) and a webhook endpoint pointing at `POST /v1/demo/webhooks` on the API itself, which verifies `X-Elapse-Signature` with `@elapse/sdk`'s `constructEvent` against the demo endpoint's secret and answers 200 or 400. It then runs four to six real test meters through the checkout services and the relayer from a wallet generated in memory, funded by one faucet drop, and forgotten when the script exits: most canceled after 20–90 seconds, one left to reach its cap. The worker restores the demo's **configuration** every six hours — seed products present and unarchived, judge-made products archived, judge-made endpoints deleted, judge-made keys revoked, the seed endpoint restored — and never deletes history; `demo:reset` runs it by hand.

## Consequences
The form can say: "Open elapse.finance/login, press Try the demo account, and enter the PIN." The PIN keeps out passers-by, not a determined attacker: a submission answer may become public, and six digits are a million guesses — years at the limits above, but the global pause means an attacker can keep judges out an hour at a time, which is accepted. A judge lands on real subscriptions, invoices, events and green deliveries, every tx link genuine, and can create products and endpoints of their own. The cost is the most work of the options weighed: a seed script that drives the real start-cancel-settle path (which doubles as an end-to-end smoke test), an allowlist middleware that must be right on the server because the UI does not hide anything, a worker timer, and a sink route. Shared state stays shared for up to six hours — one judge can see another's products — and the allowlist is the only thing between a public button and the account, so every new dashboard write route is refused to the demo until someone adds it on purpose. History only grows; nothing prunes it. The seed wallet's leftover AUSD is stranded on testnet, which costs nothing real.
